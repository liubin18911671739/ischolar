# 第06课｜大模型本地部署实战

> [!abstract] 🎯 本课定位
> 前五课你一直在“把资料交给模型”。这一课要回答一个更根本的问题：**哪些资料根本不能交出去？**
>
> **学完你将拥有**：一个断网也能跑的本地模型、一套明确的数据分级规则，以及“什么任务用云端、什么任务用本地”的判断力。

> [!warning] ⚠️ 本课不是“本地模型能替代 GPT”
> 7B 级本地模型的推理与写作能力**明显弱于**云端大模型。它的价值是**数据不出本机**，不是“更强”。

## 🚀 二、为什么需要本地部署

### 2.1 三个真实场景

| 场景 | 云端 API 的风险 | 本地模型的解法 |
| :-- | :-- | :-- |
| 未发表论文全文润色 | 内容离开本机，无法撤回 | 全程本地，断网可跑 |
| 学生访谈转写稿分析 | 含可识别个人信息 | 不联网处理 |
| 涉密/受限课题材料 | 明确规定不得上传 | 唯一合规选项 |

### 2.2 本地模型的四个局限（必须知道）

1. **能力有限**：7B 模型在长逻辑链、复杂论证上明显吃力。
2. **速度慢**：无 GPU 时，CPU 推理可能只有每秒几个字。
3. **上下文短**：常见 8K–32K，长论文需分段。
4. **幻觉仍存在**：本地不等于准确，核验照做。

> [!info] 正确的心态
> 本地模型是**保险柜里的备用工具**，不是主力生产力。日常写作用云端，敏感材料用本地。

### 2.3 适用场景判断

```text
用本地模型：
✅ 敏感材料的摘要与提纲
✅ 访谈稿初步归类（最终人工确认）
✅ 断网环境下的写作陪伴
✅ 高频、低复杂度的润色

用云端 API：
✅ 复杂论证与长文写作
✅ 需要强推理的方法设计
✅ 文献综合与批判性分析
✅ 代码调试
```

## 🛠️ 三、Ollama 安装与配置

### 3.1 安装

**macOS**

```bash
brew install ollama
# 或到 https://ollama.com/download 下载 .dmg
```

**Windows**

```powershell
# 官网下载 OllamaSetup.exe，双击安装
# 安装后自动后台运行，托盘可见羊驼图标
```

**Linux**

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

**验证**

```bash
ollama --version
```

### 3.2 拉起服务

```bash
# macOS / Linux 服务通常自动启动；手动启动：
ollama serve

# 检查是否在监听
curl http://127.0.0.1:11434/api/tags
```

### 3.3 下载与运行模型

```bash
# 中文能力与体积较平衡（约 4.7 GB）
ollama pull qwen2.5:7b

# 内存较小的机器（约 2 GB）
ollama pull qwen2.5:3b

# 推理增强版（约 4.7 GB）
ollama pull deepseek-r1:7b

# 运行
ollama run qwen2.5:7b
>>> 请用三句话说明你能做什么
```

> [!tip] 国内下载慢怎么办
> Ollama 官方源国内通常可用但速度波动。可先在 ModelScope 下载 GGUF 模型文件，再：
> ```bash
> ollama create my-qwen -f Modelfile
> # Modelfile 内容：FROM ./qwen2.5-7b-instruct-q4_k_m.gguf
> ```

### 3.4 硬件匹配表

| 内存 | 推荐模型 | 说明 |
| :-- | :-- | :-- |
| 8 GB | `qwen2.5:3b` | 轻量，速度快，质量一般 |
| 16 GB | `qwen2.5:7b` | 平衡之选，课程推荐 |
| 32 GB | `qwen2.5:14b` | 质量更好，速度可接受 |
| Apple Silicon（M 系列） | `qwen2.5:7b` | Metal 加速，体验接近入门 GPU |
| NVIDIA 8 GB+ 显存 | `qwen2.5:7b` / `14b` | GPU 加速，速度提升明显 |

### 3.5 常用命令

```bash
ollama list              # 已下载模型
ollama show qwen2.5:7b   # 模型详情
ollama ps                # 运行中的模型
ollama rm qwen2.5:3b     # 删除模型
ollama stop              # 停止
```

## 🌐 四、模型与数据集：ModelScope 与 HuggingFace

### 4.1 魔搭 ModelScope（国内首选）

```text
1. https://modelscope.cn（或 modelscope.ai）→ 注册登录
2. 「模型库」搜索 qwen / deepseek / chatglm
3. 进入模型页 →「模型文件」→ 下载 GGUF 或使用 SDK
4. 「数据集」页可按模态（文本/图像/音频）与规模筛选
```

```bash
# 命令行下载（需先 pip install modelscope）
modelscope download --model Qwen/Qwen2.5-7B-Instruct --local_dir ./models/qwen2.5-7b
```

### 4.2 HuggingFace（国际主站 + 国内镜像）

```bash
# 设置镜像（写入 ~/.zshrc 长期生效）
export HF_ENDPOINT=https://hf-mirror.com

# 下载数据集
huggingface-cli download --repo-type dataset <dataset-id> --local-dir ./data
```

> [!warning] 数据集许可要看清
> 下载页的 License 决定你能不能用、能不能发。**CC BY-NC 不能商用**；某些语料仅限研究用途。写论文时要在“数据可用性声明”里注明来源与许可。

### 4.3 选模型的三条实用标准

| 标准 | 怎么看 | 建议 |
| :-- | :-- | :-- |
| 中文能力 | 看中文榜单（C-Eval / CMMLU）与实测 | Qwen 系列中文较稳 |
| 参数量 | 7B 需要约 8 GB 内存（量化后） | 16 GB 机器选 7B |
| 量化等级 | Q4_K_M 性价比最高 | 优先 GGUF Q4 |

## ⚙️ 五、接到 iScholar 与 Hermes

### 5.1 iScholar（图形界面，最简单）

```text
左侧边栏 → 大模型与 API 秘钥设置
├── 选择模型服务商：Ollama 本地开源模型（离线免 Key）
├── Base URL：http://127.0.0.1:11434/v1
├── 模型名称：qwen2.5:7b
├── API Key：留空
└── 点击「🔌 测试连接」→ 成功提示
```

### 5.2 Hermes Profile

`~/.hermes/profiles/ollama/config.yaml`：

```yaml
name: "本地离线助手"
model: "qwen2.5:7b"
temperature: 0.3

providers:
  - name: ollama-local
    type: ollama
    base_url: "http://127.0.0.1:11434"
    model: "qwen2.5:7b"

tools:
  - read_file
  - write_file
  - search_files
```

```bash
hermes profile use ollama
hermes chat -q "用中文总结这段话：……"
```

> [!tip] 断网验证
> 关掉 Wi-Fi，再跑一次对话。如果能正常返回，说明真的走本地；如果报连接错误，说明还在走云端。

## 🔐 六、三级数据边界（本课最重要的一张表）

| 级别 | 材料类型 | 允许使用的模型 | 附加要求 |
| :-- | :-- | :-- | :-- |
| 🟢 **公开级** | 已发表论文、公开政策、公开语料、教材公开内容 | 云端国产 API（DeepSeek / 通义 / Kimi / GLM） | 记录来源与许可 |
| 🟡 **受限级** | 未发表草稿、课程设计、校内非公开材料、脱敏问卷 | 校内平台 或 本地 Ollama | 脱敏；不贴可识别信息 |
| 🔴 **敏感级** | 学生个人信息、访谈原始录音/转写、涉密课题、版权受限全文 | **仅本地 Ollama**，禁止任何外部 API | 加密存储；最小必要原则 |

### 6.1 三条落地规则

1. **默认最严**：拿不准时按 🔴 处理。
2. **脱敏再上传**：人名→编号，学校→“某高校”，地名按需泛化。
3. **留痕**：在 `04_证据与来源台账/` 记录“哪份材料、用哪个模型、何时处理”。

> [!warning] 真实翻车案例（课程常见）
> 把整班学生的作文粘进云端模型让“批量批改”，其中含姓名与学号。这既违反个人信息保护要求，也可能违反学校数据管理规定。**正确做法：先本地脱敏，再考虑是否上云；或全程本地。**

## ❓ 八、常见问题

> [!question] Q1：本地模型能写论文吗？
> 能写“骨架”，写不了“有洞察的论证”。建议：本地做提纲、摘要、脱敏材料整理；成稿用云端。

> [!question] Q2：为什么我的 Ollama 很慢？
> 检查：①是否在用 CPU 跑 14B；②是否内存不足导致换页；③是否同时开了很多应用。16 GB 机器跑 7B 是舒适区。

> [!question] Q3：Ollama 和 llama.cpp / LM Studio 什么关系？
> Ollama 底层用 llama.cpp，封装了模型管理与 API。LM Studio 是图形界面替代品，功能类似。课程选 Ollama 是因为命令行与 API 更适合自动化。

> [!question] Q4：能不能用自己的数据微调？
> 技术上可以（LoRA），但成本与门槛高，且小样本微调容易过拟合。课程不要求，先把 RAG（检索增强）用好更实际。

> [!question] Q5：本地模型会不会偷偷联网？
> Ollama 默认只监听 `127.0.0.1`，不上传对话。但如果你在 Obsidian 装了 Copilot 插件并配了云端 Key，那是另一条通道——注意区分。

> [!question] Q6：模型文件占空间太大怎么办？
> 只保留 1–2 个常用模型；`ollama rm` 删除不用的；模型默认存 `~/.ollama/models`。
