# 内容维护指南

## 课程与专题

课程来源为本次确认的 16 次培训日历及配套逐课编排，案例内容属于教学设计，不是已完成研究的实测结果。当前网站不嵌入尚未核验的 Canva 课件，也不复制旧版冲突的课时分配。

在 `src/content/courses.ts` 编辑每课的标题、简介、目标、任务、成果、工具、人工复核点和资源 ID。当前约定：16 次课、编号 01–16、每课 2 小时、每周两次。模块与专题的汇总在同文件计算，新增或调整课程必须同步审查内容规则，不要只改首页文字。

`src/content/guides.ts` 保存五个专题的流程、说明、演练案例和参考入口。官方文档链接仅作参考，不能据此声称校内已安装、批准或验证相关服务。

编辑后运行：

```bash
npm run test:content
npm run check
npm run build
```

## 资源与下载

在 `src/content/resources.ts` 维护模板，字段为稳定 ID、标题、描述、标签、文件格式和正文。课程通过 `resourceIds` 关联模板。

- Markdown 提供可填写的字段和使用说明，不放入未授权材料。
- CSV 使用一致列数，正文保持标准 CSV；下载器自动添加 UTF-8 BOM，便于中文表格软件打开。
- 资源应至少关联一门课程，方便课程筛选和全站检索。
- 下载在浏览器生成，不需要新增 API 或上传服务器。

## 站点配置

在 `src/content/site.ts` 维护日期、联系方式、提醒和平台信息。日期示例：

```ts
courseDates: {
  "01": "2026-11-03",
  "02": "2026-11-06",
}
```

以上仅为格式示例，不是正式排课日期；初始配置为空。未填写的课次仅显示周次。联系方式为空时显示“待管理员配置”；设置真实联系邮箱后才出现邮件链接。

平台、L20 及工具候选状态：

```ts
{ kind: "proposal" } // 设计建议
{ kind: "pending" } // 待校方确认
{ kind: "tested", evidence: "测试记录位置及范围", date: "YYYY-MM-DD", responsible: "测试责任方" }
{ kind: "confirmed", evidence: "确认文件位置及范围", date: "YYYY-MM-DD", responsible: "确认责任方" }
```

“已实测”和“校方已确认”在类型上要求依据、日期和责任方。依据不能放入不能公开的校内材料，可使用经批准的摘要或公开入口。确认范围不能泛化到其他用途。

## 本地数据与兼容

当前数据格式为版本 1：`completed` 保存课程 ID，`notes` 保存按课程 ID 索引的正文，`sources` 保存来源与许可登记，另有 `updatedAt`。不向服务端上传。

- 不轻易改变课程稳定 ID，否则已有进度可能失配。
- 修改数据结构时必须增加版本并设计迁移，不能直接覆盖旧记录。
- 旧格式或损坏数据会保留在存储中，暂停覆盖；JSON 导出包含 `unreadableStorageBackup`，便于人工恢复。
- 浏览器导出包含用户填写的数据，应提醒使用者保管好备份。
- 来源记录中的“有授权依据”是使用者自行登记，不等同于学校审批。

## 素材与事实边界

不添加学校徽标、虚构照片或未获授权的课程素材。示意图与演练案例明确标示性质。模型、权重、代码、数据、字体、音乐、肖像和声音分别核对许可；模型性能、L20 并发和校内平台均需依据具体确认或测试记录更新。
